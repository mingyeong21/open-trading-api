# Samsung Auto Trader

한국투자증권 Open API 모의투자 환경을 활용한 삼성전자(005930) 자동매매 시스템입니다.

이 프로젝트는 실제 수익 창출이 아니라, REST API 기반 자동매매 시스템의 기본 구조를 이해하고 구현하는 것을 목표로 합니다.
인증, 현재가 조회, 잔고 조회, 주문 요청, 체결 확인, 로그 기록, 전략 판단 과정을 모듈화하여 구현했습니다.

---

## 1. 프로젝트 개요

본 프로젝트는 한국투자증권 Open API를 사용하여 삼성전자(005930)를 대상으로 자동매매를 수행하는 Python 프로그램입니다.

주요 특징은 다음과 같습니다.

```text
- 한국투자증권 Open API 사용
- 모의투자 환경 전용
- REST API 기반 polling 방식
- WebSocket 미사용
- 삼성전자(005930) 단일 종목 대상
- 환경변수를 통한 AppKey, AppSecret, 계좌번호 관리
- 당일 access token 캐싱
- 이동평균 기반 매매 전략
- 주문 후 잔고 재조회 방식의 체결 확인
- 주요 동작 logging 처리
```

이 프로젝트에서는 실제 계좌가 아닌 모의투자 계좌를 사용합니다.
따라서 실제 자금이 투입되는 실전투자 프로그램이 아니라, 자동매매 시스템의 기본 구조를 실습하기 위한 교육용 프로젝트입니다.

## 2. 전략 개선: 고정 가격 전략에서 이동평균 전략으로

### 2.1 초기 전략: 현재가 ±2,000원 지정가 주문

처음에는 삼성전자 현재가를 조회한 뒤, 현재가를 기준으로 일정 금액 차이를 둔 지정가 주문 전략을 고려했습니다.

예를 들어 다음과 같은 방식입니다.

```text
매수 주문가 = 현재가 - 2,000원
매도 주문가 = 현재가 + 2,000원
```

이 방식은 구조가 단순하고 직관적입니다.
현재가보다 낮은 가격에 매수 주문을 넣고, 현재가보다 높은 가격에 매도 주문을 넣기 때문에 “싸게 사고 비싸게 판다”는 기본 아이디어를 쉽게 표현할 수 있습니다.

하지만 실제 모의투자 환경에서 테스트하기에는 한계가 있었습니다.

### 2.2 기존 전략의 문제점

삼성전자는 거래량이 많고 가격이 비교적 안정적인 대형주입니다.
따라서 짧은 시간 안에 현재가 기준으로 ±2,000원만큼 충분히 움직이지 않을 수 있습니다.

이 경우 다음과 같은 문제가 발생합니다.

```text
1. 매수 주문이 현재가보다 너무 낮게 들어가 체결되지 않을 수 있음
2. 매도 주문이 현재가보다 너무 높게 들어가 체결되지 않을 수 있음
3. 주문은 생성되지만 실제 거래가 발생하지 않을 수 있음
4. 주문 후 체결 확인 과정을 테스트하기 어려움
5. 2,000원이라는 고정 가격 차이에 대한 전략적 근거가 약함
```

즉, 현재가 ±2,000원 방식은 단순하지만 체결 가능성이 낮고, 자동매매 시스템의 핵심 흐름인 “전략 판단 → 주문 → 체결 확인 → 다음 판단” 과정을 충분히 보여주기 어렵다는 문제가 있었습니다.

### 2.3 개선 전략: 이동평균 기반 추세추종 전략

이를 보완하기 위해 본 프로젝트에서는 단순 이동평균 기반 추세추종 전략을 사용했습니다.

프로그램은 REST API를 통해 일정 간격으로 삼성전자의 현재가를 조회하고, 최근 가격 기록을 내부적으로 저장합니다.
그 후 단기 이동평균과 장기 이동평균을 비교하여 매수 또는 매도 여부를 판단합니다.

```text
단기 이동평균 = 최근 3번 조회한 현재가의 평균
장기 이동평균 = 최근 8번 조회한 현재가의 평균
```

여기서 3개와 8개는 분봉 데이터가 아니라, 프로그램이 REST API polling으로 수집한 현재가 개수 기준입니다.

예를 들어 polling interval이 60초라면 다음과 같이 해석할 수 있습니다.

```text
최근 3개 평균 = 3분간의 단기 가격 흐름
최근 8개 평균 = 8분간의 장기 가격 흐름
```

### 2.4 매매 규칙

본 프로젝트의 매매 규칙은 다음과 같습니다.

#### 매수 조건

삼성전자를 보유하지 않은 상태에서 다음 조건이 충족되면 1주 매수합니다.

```text
단기 이동평균 > 장기 이동평균
```

이는 최근 가격 흐름이 장기 흐름보다 강하다고 판단하는 조건입니다.

#### 매도 조건

삼성전자를 보유 중인 경우, 다음 조건 중 하나가 충족되면 1주 매도합니다.

```text
1. 현재가가 매수가 대비 +0.4% 이상 상승한 경우 → 익절
2. 현재가가 매수가 대비 -0.3% 이하로 하락한 경우 → 손절
3. 단기 이동평균이 장기 이동평균보다 낮아진 경우 → 추세 반전 매도
```

즉, 보유 중에는 수익 실현, 손실 제한, 추세 이탈 대응을 모두 고려하도록 설계했습니다.

### 2.5 주문 방식

전략은 이동평균으로 판단하지만, 실제 주문은 시장가 주문을 사용합니다.

```text
ORD_DVSN = "01"
ORD_UNPR = "0"
```

즉, 프로그램이 직접 매수 주문가나 매도 주문가를 계산하지 않고, 주문 시점의 시장에서 체결 가능한 가격으로 주문을 제출합니다.

이렇게 설계한 이유는 모의투자 환경에서 주문 체결 가능성을 높이고, 주문 후 보유 수량 변화를 통해 체결 여부를 확인하기 쉽게 하기 위해서입니다.

정리하면 다음과 같습니다.

```text
전략 판단 기준 = 이동평균
주문 방식 = 시장가 주문
주문 수량 = 1주
```

### 2.6 API 호출 제한 대응

한국투자증권 모의투자 API는 짧은 시간 안에 너무 많은 요청을 보내면 요청 제한 오류가 발생할 수 있습니다. 실제 테스트 중 `EGW00201: 초당 거래건수를 초과하였습니다` 오류가 발생했기 때문에, API 호출 간격을 보수적으로 조정했습니다.

이를 위해 한 번의 trading cycle이 끝난 뒤 다음 cycle까지 대기하는 시간을 180초로 설정했고, 주문 후 체결 여부를 확인하기 전에도 20초 동안 대기하도록 했습니다.

```text
poll_interval_seconds = 180
order_confirm_wait_seconds = 20
```

## 3. 프로젝트 구조

프로젝트 폴더 구조는 다음과 같습니다.

```text
samsung_auto_trader/
├── main.py
├── config.py
├── auth.py
├── kis_client.py
├── strategy.py
├── trader.py
├── logger.py
├── requirements.txt
├── README.md
└── .env.example
```

### `main.py`

프로그램의 시작점입니다.

```text
- 설정값 불러오기
- access token 발급 또는 재사용
- KIS API client 생성
- 매매 전략 객체 생성
- Trader 객체 생성
- 자동매매 실행 시작
```

### `config.py`

환경변수와 기본 설정을 관리하는 파일입니다.

```text
- GH_ACCOUNT, GH_APPKEY, GH_APPSECRET 불러오기
- 모의투자 API base URL 설정
- 종목코드 005930 설정
- 거래 가능 시간 설정
- polling interval 설정
- 이동평균 기간 설정
- 익절/손절 기준 설정
- 계좌번호를 CANO와 ACNT_PRDT_CD로 분리
```

### `auth.py`

한국투자증권 Open API access token 발급과 캐싱을 담당합니다.

```text
- token_cache.json 확인
- 같은 날짜에 발급된 token이 있으면 재사용
- token이 없으면 새 access token 발급
- 발급받은 token을 token_cache.json에 저장
```

### `kis_client.py`

한국투자증권 Open API와 직접 통신하는 모듈입니다.

```text
- 현재가 조회
- 계좌 잔고 및 보유 수량 조회
- 매수/매도 주문 요청
- 주문용 hashkey 발급
- API 요청 header 생성
- timeout, retry, rate limit 처리
```

### `strategy.py`

매수/매도 판단 로직을 담당합니다.

```text
- 최근 가격 기록 저장
- 단기 이동평균 계산
- 장기 이동평균 계산
- 매수 신호 판단
- 익절 조건 판단
- 손절 조건 판단
- 추세 반전 매도 조건 판단
```

이 파일은 API를 직접 호출하지 않고, 가격과 보유 상태를 바탕으로 `BUY`, `SELL`, `HOLD` 중 하나의 판단을 반환합니다.

### `trader.py`

자동매매의 전체 실행 흐름을 담당합니다.

```text
- 거래 가능 시간 확인
- 현재가 조회
- 보유 수량 조회
- 전략 판단 요청
- 매수/매도 주문 실행
- 주문 후 보유 수량 재확인
- 체결 여부 추정
- 일정 시간 대기 후 반복 실행
```

### `logger.py`

프로그램의 주요 동작을 로그로 기록합니다.

```text
- 프로그램 시작
- 현재가 조회
- 보유 수량 확인
- 이동평균 계산
- 매매 판단 결과
- 주문 요청
- 주문 응답
- 체결 확인
- API 오류
- 거래시간 종료
```

### `requirements.txt`

프로그램 실행에 필요한 Python 패키지 목록입니다.

```text
requests
python-dotenv
```

### `.env.example`

환경변수 예시 파일입니다.

```env
GH_ACCOUNT=12345678-01
GH_APPKEY=your_app_key_here
GH_APPSECRET=your_app_secret_here
KIS_BASE_URL=https://openapivts.koreainvestment.com:29443
```

실제 인증정보는 GitHub Codespaces Secrets 또는 로컬 `.env`에서 관리해야 하며, GitHub repository에 업로드하지 않습니다.

## 4. 주요 코드 흐름

프로그램의 전체 실행 흐름은 다음과 같습니다.

```text
1. main.py 실행
2. config.py에서 환경변수와 설정값 로드
3. auth.py에서 access token 발급 또는 당일 token 재사용
4. kis_client.py에서 KIS API client 생성
5. strategy.py에서 이동평균 전략 객체 생성
6. trader.py에서 자동매매 루프 실행
```

자동매매 루프 내부 흐름은 다음과 같습니다.

```text
1. 현재 시간이 거래 가능 시간인지 확인
2. 거래 가능 시간이 아니면 주문하지 않고 대기
3. 삼성전자 현재가 조회
4. 최근 가격 기록 업데이트
5. 계좌의 삼성전자 보유 수량 조회
6. 단기 이동평균과 장기 이동평균 계산
7. 전략에 따라 BUY, SELL, HOLD 중 하나 결정
8. BUY 또는 SELL이면 시장가 주문 제출
9. 주문 후 일정 시간 대기
10. 잔고를 다시 조회하여 보유 수량 변화 확인
11. 보유 수량이 변했으면 체결된 것으로 추정
12. polling interval 동안 대기 후 다음 cycle 반복
```

예를 들어 매수 체결 확인은 다음 방식으로 이루어집니다.

```text
주문 전 보유 수량 확인
→ 매수 주문 제출
→ 일정 시간 대기
→ 주문 후 보유 수량 재조회
→ 보유 수량이 증가하면 매수 체결로 판단
```

매도 체결 확인은 다음 방식으로 이루어집니다.

```text
주문 전 보유 수량 확인
→ 매도 주문 제출
→ 일정 시간 대기
→ 주문 후 보유 수량 재조회
→ 보유 수량이 감소하면 매도 체결로 판단
```

이 방식은 체결내역 API를 직접 조회하는 방식보다 단순하지만, 모의투자 자동매매 시스템에서 주문 결과를 확인하는 기본적인 방법입니다.
